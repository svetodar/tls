# task 17 — X25519 (Curve25519 Diffie–Hellman)

Layer 1. Dependencies: 01 (BN), 02 (CSPRNG). Optional for TLS 1.3 (task 13),
where X25519 is the preferred `key_share` group.

## Goal

Implement X25519 as specified by RFC 7748: scalar multiplication on the
Montgomery curve Curve25519 with the standard base point u = 9. This is the
modern (EC)DHE key exchange used by TLS 1.3 and by many TLS 1.2 deployments.

## File

`src/tls.x25519.pas`, tests in `tests/test_x25519.pas`.

## What to implement

- Field arithmetic over GF(2^255 − 19) in radix 2^51 (five 64-bit limbs):
  `FeAdd`, `FeSub`, `FeMul`, `FeSqr`, `FeMul121665` (the `a24` term),
  `FeInvert` (`z^(p−2)` by an addition chain) and `FeCswap`.
- A constant-structure Montgomery ladder over bits 254…0 of the clamped
  scalar; the conditional swap is arithmetic (no branch on scalar bits).
- Scalar clamping (`k[0] &= 248`, `k[31] &= 127`, `k[31] |= 64`), masking
  bit 255 of the u-coordinate (RFC 7748 §5), little-endian 32-byte I/O.
- Public API: `X25519`, `X25519PublicKey`, `X25519SharedSecret`,
  `X25519GenerateKeyPair`, `X25519Clamp`, `TX25519KeyPair`, `EX25519Error`.
- `X25519SharedSecret` rejects the all-zero output produced by low-order
  peer public keys (`EX25519Error`), matching the TLS requirement.

## Acceptance criteria

- RFC 7748 §5.2 raw scalar-multiplication vectors.
- RFC 7748 §5.2 iterated test (1,000 iterations).
- RFC 7748 §6.1 Diffie–Hellman test: both public keys and the shared secret.
- Bit 255 of the u-coordinate is ignored; clamping is applied as specified.
- Low-order points (u = 0, 1, p−1) yield the all-zero value and
  `X25519SharedSecret` rejects them.
- Differential testing against an independent reference over random and
  edge-case inputs (including representatives of the form p + small).
- `make test` passes; tests — `tests/test_x25519.pas`.

## Implementation notes

Field products can carry out of limb 9 into 2^510 = 19^2 = 361 (mod p) when
an intermediate limb equals 2^51 (for example the representative p + 256);
that carry must be folded, otherwise results in low-order-point paths are
wrong. `FeMul` folds both the limbs 5…9 and the final carry.
