Layer 2 (`tls.certstore`, `tls.roottable`, `tls.roots`). Dependencies: 3
(SHA-256), 10 (X.509), 11 (chain verification / trust store).

## Goal

Ship the root CAs inside the executable, so a consumer does not depend on a
PEM file lying next to the binary, on the layout of `/etc/ssl`, or on the
state of the OS store. A DER table of trusted roots is embedded as an
`RT_RCDATA` resource of the library unit `tls.roots`, read lazily once per
process, integrity-checked with SHA-256 and turned into a `TCertStore` that
`VerifyChain` accepts. The PEM text stays the source of truth in git
(`certs/roots.pem`); the resource is generated by `make roots` and is not
committed.

Preconditions checked in `result.md`: `{$R file.res}` in a *unit* is linked
into the host executable on all FPC targets, the resource is readable in
under 1 ms, and the exe grows by about the size of the bundle (≈139 KB DER
for the full Mozilla/certifi set). No external crypto dependency is added:
base64, DER parsing and SHA-256 already exist in this library.

## What to implement

### `tls.certstore.pas`

Pure "memory instead of a file"; no knowledge of resources or of the DER
table format.

- `LoadPEMFromMemory(const APEM: RawByteString): TX509Cert` — parse the first
  `-----BEGIN CERTIFICATE-----` block of a string, return a `TX509Cert` the
  caller owns. Errors — `EASN1Error` (no block, bad base64, malformed DER).
- `LoadBundleFromStream(AStream: TStream): TCertStore` — read the stream to
  the end and load every certificate block into a new `TCertStore`; the store
  owns the parsed certificates (`AddOwnedCert`). Errors — `EASN1Error`.
- `LoadBundleFromMemory(const APEM: RawByteString): TCertStore` — same reader
  over a string.
- `LoadBundle(const APath: string): TCertStore` — reimplemented as a thin
  wrapper that opens a `TFileStream` and calls `LoadBundleFromStream`; the
  doc comment keeps its current contract (errors, ownership).
- `LoadPEM` keeps its signature and becomes a wrapper over
  `LoadPEMFromMemory` reading the file.

Note: `result.md` §5.2 sketched `LoadBundleFromMemory` as taking a DER table
(`ADerTable: TBytes`). The DER-table reader lives in `tls.roottable` instead,
so `tls.certstore` stays free of the bundle format and the two units do not
depend on each other; `LoadBundleFromMemory` here mirrors
`LoadBundleFromStream` for PEM text.

### `tls.roottable.pas`

No OS calls, no file access — only bytes in, bytes/structure out.

- `ECertBundleError = class(Exception)` — typed error for a malformed,
  truncated or corrupted bundle.
- Format constants (little-endian `uint32` unless stated otherwise):

  ```
  header (fixed): magic 'TLSROT' (6 bytes) + version:uint8 + flags:uint8
                  count:uint32 + snapshotDate:uint32 (Unix days)
                  dataSha256:32          -- SHA-256 of everything after count+date+hash
  record:         derOffset:uint32 + derLength:uint32 + subjectHash:uint32
                  skiPresent:uint8 + ski[0..19] + trust:uint8
  then            count × DER certificate, back-to-back, no padding
  ```

  `trust` is a bit mask: `web`, `email`, `code`, `distrusted`; a distrusted
  root is never used as a trust anchor. `derOffset` is relative to the start
  of the table.
- `TEmbeddedRoots`/`TRootEntry` — decoded header plus a record array; accessors
  `Count`, `Entry(i)`, `SnapshotDate`, `DataSha256` (raw bytes), and a
  `CertificateDer(i)` slice.
- `DecodeRootTable(const ATable: TBytes): TRootTable` — validates magic,
  version, `count` bounds, every record's offsets and lengths, SKI length and
  the `dataSha256` field; raises `ECertBundleError` with a reason for the
  first violated invariant.
- `BuildCertStore(const ATable: TBytes; AIncludeDistrusted: Boolean = False):
  TCertStore` — decode, then parse every included DER with `ParseCertificate`
  and `AddOwnedCert` it into a fresh store; skipped entries never fail the
  whole bundle unless `AIncludeDistrusted` asks for them.

### `tools/rootsgen/rootsgen.lpr`

Standalone program (not part of the test run), pure Pascal, no openssl/python.

- Inputs: `certs/roots.pem` (PEM blocks in a stable order), `certs/roots.date`
  (one `YYYY-MM-DD` line, the snapshot date), optional
  `certs/distrusted.txt` (one SHA-256 fingerprint per line, `#` comments).
- Sort records deterministically: by `subjectHash`, then by SHA-256 of the DER,
  so that the same inputs always produce a byte-identical table.
- Compute `subjectHash` with the same canonicalisation `VerifyChain` uses
  (lower-case, collapsed blanks); compute `dataSha256` over the block that
  follows it.
- Emit the table, write `build/roots/tlsroots.rc`
  (`TLSROOTS RCDATA "roots.bin"`) and call `fpcres tlsroots.rc -o
  src/tlsroots.res -of res`. Windows and Unix both use the resource reader of
  FPC, so one `.res` serves every target.
- Print `count`, `snapshot date` and `dataSha256` (hex) and the new file sizes;
  exit non-zero on any malformed input or when `fpcres` fails.

### `tls.roots.pas`

The only unit that names the resource.

- `{$R tlsroots.res}` (skipped under `{$ifndef TLS_NO_EMBEDDED_ROOTS}`), name
  `TLSROOTS`, type `RT_RCDATA`. `RT_RCDATA` on Windows comes from `windows`,
  elsewhere from `System`:
  `uses Classes, SysUtils {$ifdef windows}, Windows {$endif}`.
- `EmbeddedRoots: TCertStore` — lazy, built once per process from the resource
  via `tls.roottable`, guarded by a `TCriticalSection` with double-checked
  initialisation. The unit owns the store; callers must not free it.
- `EmbeddedRootsDate: TDateTime` — snapshot date from the table header.
- `EmbeddedRootsIsStale(const ANow: TDateTime;
  AMaxAgeDays: LongInt = 365): Boolean` — a flag, not an error.
- `ReleaseEmbeddedRoots` — free the cached store (tests, leak checks); the
  next call rebuilds it.
- The resource bytes are hashed before decoding; a mismatch raises
  `ECertBundleError` ("embedded roots are corrupted"), never silently falls
  back to an empty store. The digest is recomputed over the payload region and
  compared with the header field, byte by byte without an early exit.
- `VerifyEmbeddedRootsSha256(const ATable: TBytes)` is that same check exposed
  in the interface, so tests can feed it tampered and truncated bytes: a
  resource linked into the executable cannot be corrupted at run time.
- Under `TLS_NO_EMBEDDED_ROOTS` the unit still compiles and `EmbeddedRoots`
  raises `ECertBundleError` ("built without embedded roots").

### `certs/`

- `certs/roots.pem` — snapshot of the Mozilla root program as published in
  certifi's `cacert.pem`, with provenance (source URL, retrieval date) noted
  in `certs/README.md`.
- `certs/roots.date` — the snapshot date used in the table header.
- `certs/distrusted.txt` — fingerprints of roots marked distrusted in Mozilla
  `certdata.txt` (may be empty for the first snapshot, with a comment saying
  so). Certificates are public data: nothing secret is committed here.

### Tests

- `tests/test_certverify.pas`: `LoadPEMFromMemory` returns the same
  certificate as `LoadPEM` for an existing fixture; `LoadBundleFromStream`
  over a stream and `LoadBundleFromMemory` over a string built from two
  existing fixtures both yield `Count = 2` and find both subjects;
  `LoadBundle` on the same fixture file still works; a stream without a
  certificate block raises `EASN1Error`.
- `tests/test_roots.pas` (`TRootsTests`, registered in
  `tests/testrunner.lpr`):
  - resource is present, `count > 0`, and `count`, snapshot date and
    `dataSha256` equal the constants pinned in the test (regenerated together
    with the snapshot by `make roots`);
  - a well-known root (ISRG Root X1) is found in `EmbeddedRoots` by subject
    and `VerifyChain(EmbeddedRoots, root)` succeeds;
  - a published chain from `tests/fixtures` verifies when the table is built
    from a small hand-made table of the same fixtures (reader + store path),
    and fails with a reason when the root is not in the table;
  - `EmbeddedRootsIsStale` is `False` at the snapshot date, `True` beyond
    `AMaxAgeDays`, and honours a custom `AMaxAgeDays` and a future `ANow`;
  - truncated table, wrong magic, wrong version, out-of-range record and a
    flipped byte (SHA-256 mismatch) each raise `ECertBundleError`, both in
    `DecodeRootTable` and through the resource-level check;
  - `ReleaseEmbeddedRoots` followed by `EmbeddedRoots` rebuilds the store, and
    `make leaktest` shows no leak.

## Acceptance criteria

- `make roots` regenerates `src/tlsroots.res` from `certs/` and is
  deterministic: two runs on the same inputs produce byte-identical output.
- `EmbeddedRoots.Count > 0`, the snapshot contains a well-known CA (ISRG Root
  X1) and `VerifyChain(EmbeddedRoots, ISRG Root X1)` succeeds.
- The resource is read and decoded in a few milliseconds at first use and is
  cached afterwards (no repeated parsing); initialisation is thread-safe.
- Every malformed or corrupted table raises `ECertBundleError` with a reason;
  no partial store is ever returned.
- `EmbeddedRootsIsStale` reports the snapshot age and the snapshot date is
  available through `EmbeddedRootsDate`.
- The existing file-based path is unchanged: `LoadPEM`/`LoadBundle` keep their
  signatures and behaviour, and their tests still pass.
- `make test` passes with the new tests; `make leaktest` reports no leaks;
  `make check-no-openssl` still finds no OpenSSL unit reference.
- The same test run passes on a Linux FPC target (resource linked by the
  compiler, no `fpcres` needed at runtime). This was not verified on the
  Windows working machine; the Linux run is therefore a separate follow-up
  stage with its own acceptance record (see *Follow-up stages*), not a
  condition of this task being done here.
- No new external dependency: the generator may use `fpcres`, the library may
  not use it at run time.

## Out of scope

- Integration into a consuming application (using `EmbeddedRoots` as the
  default trust source and removing the "put ca-bundle.pem next to the
  program" message) — a separate step in the host project.
- Automatic download of a fresh snapshot or of Mozilla `certdata.txt`;
  the snapshot is updated by a maintainer and committed.
- Making the embedded bundle the default in `TTLSSocketHandler`; the
  trust-source order is documented here and wired up in the follow-up task.
- Signing the resource beyond SHA-256 integrity checking (code signing of the
  host exe is the consumer's concern).

## Follow-up stages

This task was implemented and verified on the Windows x86_64 FPC 3.2.2 target
(`make roots` with the Windows `fpcres`, `make test` → 385 tests green,
`make leaktest`). Two stages are explicitly **not** part of it; each is tracked
on its own and gets its own record here or in `docs/progress.md` when done.

### 1. Linux FPC 3.2.2 verification run

- Regenerate the resource with the Linux `fpcres`
  (`make roots` on a Linux x86_64 host) and confirm that
  `src/tlsroots.res` is byte-identical to the file produced on Windows; the
  generator is already deterministic, so a difference would mean `fpcres`
  writes the resource differently per platform and would have to be understood
  before the file is accepted as a build input.
- Run `make test`, `make leaktest` and `make check-no-openssl` and record the
  test count.
- Only then may the "Linux target" part of the acceptance criteria be marked
  satisfied. Nothing in the units is expected to change: `{$R tlsroots.res}` is
  linked by the compiler on every FPC target, `RT_RCDATA` resolves from
  `System` instead of `windows`, and `tls.rand` reads `/dev/urandom`.

### 2. Integration into the consuming `subag` project

- Bump the `deps/tls` submodule to the commit that ships `tls.roots`.
- Make `EmbeddedRoots` the default trust source in the host's TLS setup and
  drop the "put ca-bundle.pem next to the program" message; the host keeps the
  documented order explicit store → embedded roots → OS store → explicit
  opt-out (`DisableSystemStore`/`DisableEmbeddedRoots` style opt-out stays
  available).
- Surface `EmbeddedRootsDate`/`EmbeddedRootsIsStale` in the host diagnostics
  instead of silently using an aging snapshot.
- This change lives in the host repository and is a separate pull request; the
  library must not grow host-specific names, paths or messages
  (`AGENTS.md`, "Architecture rules").
