# task 13 — TLS 1.3 (client)

Layer 3. Dependencies: 01–11, 12 (TLS 1.2). Lower priority — optional
extension after TLS 1.2.

## Goal

Implement the client side of TLS 1.3 (RFC 8446): updated handshake
(1-RTT), HKDF-based key schedule, mandatory AEAD, no RSA key exchange.

## File

`src/tls.tls13.pas`

## What to implement

- **Key schedule** (HKDF, RFC 5869): `HKDF-Extract`/`HKDF-Expand` based on
  HMAC-SHA256; derivation of `derived_secret`, `handshake_secret`,
  `master_secret`, `client/server_handshake_traffic_secret`,
  `client/server_application_traffic_secret`.
- **Handshake (client)**:
  - `ClientHello` (version 0x0304, supported_versions ext, key_share
    (X25519/P-256), psk_key_exchange_mode).
  - `ServerHello` + `EncryptedExtensions` + `Certificate` +
    `CertificateVerify` + `Finished` (encrypted).
  - Client `Finished`.
- **Cipher suites**: `TLS_AES_128_GCM_SHA256`, `TLS_AES_256_GCM_SHA384`,
  `TLS_CHACHA20_POLY1305_SHA256`.
- **Key exchange**: (EC)DHE via `key_share` (X25519 optional, P-256/P-384).
  RSA key exchange is absent in 1.3.
- **Record layer**: same as in 1.2, but AEAD only, sequence numbers,
  `ChangeCipherSpec` — legacy record.
- **Verification**: `CertificateVerify` (ECDSA/RSA-PSS) + chain (task 11).
- Reuse `ITLSTransport` and the record layer from task 12.

## Acceptance criteria

- Handshake with a real TLS 1.3 server completes; data exchange works.
- Key schedule matches the server (successful exchange is the proof).
- `CertificateVerify` is verified; invalid → reject.
- Tests — `tests/test_tls13.pas`.

## OpenSSL references

- `ssl/tls13_enc.c` (key schedule, HKDF, record), `ssl/t1_lib.c`
  (common handshake), `ssl/record/rec_layer_tls.c` (record 1.3),
  `ssl/ssl_ciph.c` (cipher suites).

## Status

Done. `src/tls.tls13.pas` implements HKDF (RFC 5869), the key
schedule, the AEAD-only record layer, the 1-RTT client handshake and
`TTLS13Client`. Tests are in `tests/test_tls13.pas` (HKDF, key schedule,
record layer, message encoders/parsers, CertificateVerify) and
`tests/test_tls13_e2e.pas` (four end-to-end sessions against
`openssl s_server -tls1_3`: RSA and ECDSA with `TLS_AES_128_GCM_SHA256`, plus
`TLS_AES_256_GCM_SHA384` and `TLS_CHACHA20_POLY1305_SHA256`).

Acceptance criteria:

- [x] Handshake with a real TLS 1.3 server completes; data exchange works
  (`GET /` returns `HTTP/1.0 200` over the encrypted channel).
- [x] The key schedule matches the server (successful handshake with all
  three mandatory cipher suites; HKDF/key schedule additionally checked
  against RFC 5869, RFC 8448 §3 and an independent reference).
- [x] `CertificateVerify` is verified (ECDSA P-256/P-384 and
  `rsa_pss_rsae_sha256`); an invalid signature or chain is rejected by
  `ETLS13Error`.
- [x] Tests — `tests/test_tls13.pas`, registered in `tests/testrunner.lpr`.

### Limitations

- HelloRetryRequest, PSK resumption/0-RTT and post-handshake `KeyUpdate` are
  rejected with a clear error; 0-RTT is not implemented.
- The RSA PSS code is SHA-256 based, so only `rsa_pss_rsae_sha256` is
  advertised; the SHA-384/512 PSS schemes are omitted.
- E2E tests require the `openssl` CLI and the regenerated fixture keys
  (`make fixtures`); otherwise they are skipped rather than failing.
