# task 13 — TLS 1.3 (client)

Layer 3. Dependencies: 01–11, 12 (TLS 1.2). Lower priority — optional
extension after TLS 1.2.

## Goal

Implement the client side of TLS 1.3 (RFC 8446): updated handshake
(1-RTT), HKDF-based key schedule, mandatory AEAD, no RSA key exchange.

## File

`src/tls.tls13.pas`

## What to implement

- **Key schedule** (HKDF, RFC 5869): `HKDF-Extract`/`HKDF-Expand` based on
  HMAC-SHA256; derivation of `derived_secret`, `handshake_secret`,
  `master_secret`, `client/server_handshake_traffic_secret`,
  `client/server_application_traffic_secret`.
- **Handshake (client)**:
  - `ClientHello` (version 0x0304, supported_versions ext, key_share
    (X25519/P-256), psk_key_exchange_mode).
  - `ServerHello` + `EncryptedExtensions` + `Certificate` +
    `CertificateVerify` + `Finished` (encrypted).
  - Client `Finished`.
- **Cipher suites**: `TLS_AES_128_GCM_SHA256`, `TLS_AES_256_GCM_SHA384`,
  `TLS_CHACHA20_POLY1305_SHA256`.
- **Key exchange**: (EC)DHE via `key_share` (X25519 optional, P-256/P-384).
  RSA key exchange is absent in 1.3.
- **Record layer**: same as in 1.2, but AEAD only, sequence numbers,
  `ChangeCipherSpec` — legacy record.
- **Verification**: `CertificateVerify` (ECDSA/RSA-PSS) + chain (task 11).
- Reuse `ITLSTransport` and the record layer from task 12.

## Acceptance criteria

- [x] Handshake with a real TLS 1.3 server completes; data exchange works —
  `tests/test_tls13_e2e.pas` starts `openssl s_server -tls1_3 -www` and drives
  the whole 1-RTT handshake with `TTLS13Client` plus an HTTP exchange in three
  configurations: `TLS_AES_128_GCM_SHA256` over P-256 with an RSA certificate,
  the same suite/group with an ECDSA certificate, and
  `TLS_AES_256_GCM_SHA384` over P-384. Manually re-confirmed against four
  openssl configurations (AES-128-GCM/P-256 RSA + ECDSA, AES-256-GCM/P-384,
  ChaCha20-Poly1305) with `tests/tools/tls13_client.pas`.
- [x] Key schedule matches the server — `TLS13DeriveKeySchedule` (early,
  derived, handshake, master and the four traffic secrets) is checked against
  the RFC 8448 §3 trace for SHA-256, the RFC 8448 PSK early secret, an
  independent SHA-384 reference (`openssl kdf`, `python3`) and the aggregate
  consistency test; the successful handshake with the server is the
  end-to-end proof.
- [x] `CertificateVerify` is verified; invalid → reject —
  `VerifyTLS13CertificateMessage` + `VerifyTLS13ECDSASignature` /
  `VerifyTLS13RSAPSSSignature`, with the RFC 8446 §4.4.3 content string; a bad
  signature, a mismatched key type or a malformed body raises `ETLS13Error`.
- [x] Tests — `tests/test_tls13.pas` (38 tests: HKDF/Expand-Label, key
  schedule, key_share, ClientHello, handshake parsers, record layer, Finished,
  explicit rejections) and `tests/test_tls13_e2e.pas` (3 E2E); both registered
  in `tests/testrunner.lpr`.

## Status: done (milestone F, 2026-10-12, Linux)

Implemented in pure FPC 3.2.2. `make test` — **301 tests, 0 errors,
0 failures**; `make check-no-openssl` — no OpenSSL unit references.

### What was done

- `src/tls.tls13.pas` — HKDF (RFC 5869): `HKDFExtract`/`HKDFExpand` over
  HMAC-SHA256/384/512, `TLS13HkdfLabel` + `HKDFExpandLabel` with the `tls13 `
  prefix (RFC 8446 §7.1). Key schedule: `TLS13EarlySecret`,
  `TLS13DerivedSecret`, `TLS13HandshakeSecret`, `TLS13MasterSecret`, the four
  traffic secrets and the aggregate `TTLS13KeySchedule` /
  `TLS13DeriveKeySchedule` (no PSK → IKM = HashLen zero bytes).
- TLS 1.3 constants (RFC 8446): version `0x0304` (legacy `0x0303`), cipher
  suites `0x1301`/`0x1302`/`0x1303`, handshake message and extension codes,
  PSK key exchange modes, legacy content types.
- `key_share` on P-256/P-384: `TLS13KeyShareGenerate`, `TLS13EncodeKeyShare`,
  `TLS13KeyShareSecret` (shared secret = X coordinate of the (EC)DHE point);
  X25519 is recognized but not offered (the task allowed it to be optional).
- `ClientHello`: SNI (reused from `tls.tls12`), `supported_versions`,
  `supported_groups`, `signature_algorithms`, `key_share`,
  `psk_key_exchange_modes` via `BuildTLS13ClientHello` /
  `WriteTLS13ClientHello`; signature schemes are restricted to
  `ecdsa_secp256r1_sha256`, `ecdsa_secp384r1_sha384` and
  `rsa_pss_rsae_sha256` (`TLS13SignatureSchemeSupported`).
- Parsers: `ServerHello` (legacy_version, `legacy_session_id_echo`, suite out
  of `0x1301/02/03`, compression, mandatory `supported_versions` and
  `key_share`); HelloRetryRequest is detected by the RFC 8446 §4.1.3 sentinel
  random and rejected with an explicit `ETLS13Error`;
  `EncryptedExtensions` (duplicate-extension check);
  `Certificate` in TLS 1.3 format (request context, entry list, per-entry
  extensions); chain verification reuses `TTLS12CertChain.Verify` /
  `TCertStore`.
- `CertificateVerify` (RFC 8446 §4.4.3): content =
  `0x20 * 64 || context string || 0x00 || Transcript-Hash`;
  `VerifyTLS13ECDSASignature` (ECDSA P-256/P-384 via `tls.ec`) and
  `VerifyTLS13RSAPSSSignature` (`rsa_pss_rsae_sha256` via
  `TRSAKey.VerifyPSS`).
- Record layer 1.3 (RFC 8446 §5): `TTLS13RecordKeys` /
  `TLS13DeriveRecordKeys` (`key`/`iv` via HKDF-Expand-Label),
  `nonce = iv XOR seq_num`, AAD = record header,
  `TLS13ProtectRecordFragment` / `TLS13UnprotectRecordFragment`; inner
  plaintext = `content || content_type || 0^padding`
  (`TLS13EncodeInnerPlaintext`/`TLS13DecodeInnerPlaintext`); legacy
  `ChangeCipherSpec` records are ignored.
- `Finished`: `TLS13FinishedKey` + `TLS13VerifyData` with a constant-time
  comparison (`TLS13ConstantTimeEquals`).
- `TTLS13Client` — `Connect`/`Send`/`Recv`/`Shutdown`/`Close`,
  `HandshakeDone`, `CipherSuite`, `CertChain`, `PendingBytes`. It drives the
  handshake, switches to application keys after the server `Finished`,
  verifies the server `Finished`, and handles post-handshake messages
  (NewSessionTicket is ignored, KeyUpdate is rejected). The transport stays
  `ITLSTransport`, so the client is testable in memory.
- `ETLS13Error` (derived from `ETLS12Error`) is raised for every malformed or
  unsupported input: unknown cipher suite/group/signature scheme,
  HelloRetryRequest, truncated or malformed handshake bodies, bad
  `CertificateVerify`.
- `tests/tools/tls13_client.pas` — standalone manual checker (not part of the
  test run): full handshake, chain verification, HTTPS GET, prints the
  negotiated suite, leaf subject and HTTP status.

### Limitations

- HelloRetryRequest is not implemented: it is detected and rejected with an
  explicit `ETLS13Error` (no silent restart). 0-RTT/early data and PSK
  resumption are not supported — NewSessionTickets are ignored.
- No client certificates; `certificate_request_context` must be empty.
- `key_share` offers P-256 and P-384 only; X25519 is recognized but not
  offered, and AES-CCM/other suites are unsupported.
- Only the three mandatory AEAD suites (`TLS_AES_128_GCM_SHA256`,
  `TLS_AES_256_GCM_SHA384`, `TLS_CHACHA20_POLY1305_SHA256`) exist; RSA
  PKCS#1 v1.5 signatures and Ed25519 are not accepted.
- Server `KeyUpdate` requests are rejected rather than honoured.
- E2E tests require the external `openssl` binary and the `tests/fixtures/
  leaf_*` files; when they are absent the tests are skipped instead of failing.
