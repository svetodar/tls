# task 12 — TLS 1.2 (client)

Layer 3. Dependencies: 01–11 (all primitives + verification).

## Goal

Implement the client side of TLS 1.2 (RFC 5246): handshake, record layer,
cipher suite selection, SNI, key generation. This is the core of an HTTPS client.

## File

`src/tls.tls12.pas` (+ `tls.prf.pas` for PRF)

## What to implement

- **PRF** (TLS 1.2): `PRF(secret, label, seed)` based on HMAC-SHA256/384
  (P_hash). Derivation of master secret, key block, IV, keys.
- **Record layer**: records (type, version, length, fragment); encryption/
  decryption of fragments with the selected cipher suite (AES-GCM/CBC,
  ChaCha20-Poly1305), MAC/integrity.
- **Handshake (client)**:
  - `ClientHello`: version, random, session_id, cipher suites, extensions
    (SNI, supported_groups, signature_algorithms, elliptic_curves).
  - `ServerHello`: cipher suite selection, random.
  - `Certificate` (+ `ServerKeyExchange` for ECDHE/DHE), `ServerHelloDone`.
  - `ClientKeyExchange` (ECDHE/DHE/RSA), `ChangeCipherSpec`, `Finished`.
  - `VerifyData` = PRF(master_secret, 'client finished'/'server finished',
    handshake_hashes).
- **Cipher suites** (priority):
  - `ECDHE-RSA-AES128-GCM-SHA256`, `ECDHE-RSA-AES256-GCM-SHA384`
  - `ECDHE-ECDSA-AES128-GCM-SHA256`, `ECDHE-ECDSA-AES256-GCM-SHA384`
  - (optional) `DHE-RSA-AES256-GCM-SHA384`, `AES128-GCM-SHA256` (static RSA).
- **Verification**: server signature verification (ServerKeyExchange /
  Certificate) + certificate chain verification (task 11) + SNI.
- **Transport abstraction**: read/write over an arbitrary stream
  (socket) — the `ITLSTransport` interface (Read/Write), so that the unit
  does not depend on the socket directly.

## Acceptance criteria

- Full handshake with a real TLS 1.2 server (local `openssl s_server`
  / `stunnel` / mock) completes; data is exchanged.
- `Finished` on both sides is correct (VerifyData matches).
- ECDHE: shared secret and keys match the server (successful data
  exchange is the proof).
- Certificate verification: invalid/unsigned → rejection.
- Tests — `tests/test_tls12.pas` (mock transport + real server in E2E).

## OpenSSL references

## Status: done (milestone D, 2026-10-12, Linux)

Implemented in pure FPC 3.2.2. `make test` — **248 tests, 0 errors,
0 failures**.

### What was done

- `src/tls.prf.pas` — TLS 1.2 PRF: `PHash` over HMAC-SHA256/384/512,
  `TLS12PRF`/`TLS12PRFSHA256`/`TLS12PRFSHA384`; derivation of master secret (regular
  and EMS/RFC 7627) and key block (`TTLS12KeyBlock`, `TLS12KeyBlock`,
  `TLS12KeyBlockRaw`, `TLS12SplitKeyBlock`, `TLS12KeyBlockLength`). Seed order
  for key block — `server_random + client_random` (RFC 5246 §8.1).
- `src/tls.tls12.pas` — record layer (2^14 limit, `ETLS12Error`,
  `ETLS12Error` for unknown type/truncation), AEAD record encryption
  (AES-GCM RFC 5288, ChaCha20-Poly1305 RFC 7905), assembly/parsing
  of handshake messages and flights (`TTLSHandshakeBuffer` + transcript),
  ClientHello (SNI, supported_groups, signature_algorithms, EMS,
  renegotiation_info, SCSV), parsing of ServerHello / Certificate /
  ServerKeyExchange / ServerHelloDone, ClientKeyExchange ECDHE P-256/P-384
  and DHE, CCS, Finished/VerifyData, Alerts. Transport — `ITLSTransport`
  (`Read`/`Write`/`BytesAvailable`) and adapter `TTLSStreamTransport` over
  `TStream`.
- `src/tls.rsa.pas` — `TRSAKey.FromPublic`/`FromPublicBytes` and
  RSAES-PKCS1-v1_5 (`EncryptPKCS1v15`/`DecryptPKCS1v15`, block type 02).
- `src/tls.certstore.pas` — `VerifyDataSignature` (signature of
  arbitrary data with the certificate's public key).
- Only AEAD suites are supported; CBC/static-RSA are recognized by name but
  explicitly restricted (`TLS12CipherSuiteSupported`/`TLS12CheckCipherSuiteSupported`).

### Acceptance criteria

- [x] Full handshake with a real TLS 1.2 server — `tests/test_tls12_e2e.pas`
  starts `openssl s_server -tls1_2 -www` and performs the handshake +
  HTTP exchange in two configurations: `ECDHE-RSA-AES128-GCM-SHA256`
  (`leaf_rsa.crt/key`, `ca_rsa.crt`) and `ECDHE-ECDSA-AES128-GCM-SHA256`
  (`leaf_ec.crt/key`, `ca_ec.crt`).
- [x] `Finished`/VerifyData on both sides — `TLS12VerifyData` /
  `TLS12VerifyFinished` (constant-time comparison); verified on
  mock transport and in E2E.
- [x] ECDHE: shared secret and keys match the server — proof:
  HTTP request `GET /` and response `HTTP/1.0 200` over the encrypted channel.
- [x] Certificate verification: invalid/unsigned → rejection
  (`TTLS12CertChain.Verify` via `TCertStore`,
  `VerifyTLS12ServerKeyExchange` for the SKE signature — RSA PKCS#1 v1.5 and ECDSA).
- [x] Tests — `tests/test_tls12.pas` (28 tests: mock transport, record layer,
  server flight, CCS, Finished, Alert) and `tests/test_tls12_e2e.pas` (2 E2E);
  both registered in `tests/testrunner.lpr`.

### Limitations

- CBC and static-RSA cipher suites are not implemented (deliberately — AEAD only).
- Session resumption (`session_id` in ClientHello is always empty) and
  client certificates are not supported.
- E2E tests require the external `openssl` binary and the fixtures `tests/fixtures/
  leaf_*`; if they are absent, the tests are skipped rather than failing.
